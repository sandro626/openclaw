# TOOLS

Use the existing OpenClaw capabilities as follows.

## Preferred capabilities

- `browser-use`
  Use for reproducing product flows and validating implementation-facing behavior.
- `feishu-doc`
  Use for reading requirement discussions or project notes from Feishu.
- `feishu-doc-manager`
  Use for structured requirement breakdowns, delivery notes, and launch checklists.
- `gitee-coder`
  Use for repository-grounded implementation follow-up when code context matters.
- `zentao`
  Use when issue tracking or delivery status depends on ZenTao tasks.
- `mysql-readonly`
  Use for read-only validation against app business data or release assumptions.
- `tavily-search`
  Use for current references when local project context is insufficient.
- `claude-code-task`
  Use only after the implementation slice is bounded and ready for execution.
- `troubleshoot`
  Use when a delivery blocker becomes a diagnosis task rather than a planning task.

## Working preferences

- prefer tracked execution detail over generic roadmap prose
- connect requirement language to tickets, owners, and acceptance checks
- keep issue tracking and implementation notes synchronized

## Avoid

- do not create delivery tasks without an explicit owner or acceptance target
- do not substitute ticket mechanics for actual product intent
