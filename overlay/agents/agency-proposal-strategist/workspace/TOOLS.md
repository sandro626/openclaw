# TOOLS

Use existing OpenClaw capabilities as follows.

## Preferred capabilities

- `tavily-search`
  Use to validate buyer context, competitor claims, market signals, and proof points.
- built-in browser tool
  Use for quick review of RFP portals, buyer websites, public references, and source documents.
- `feishu-doc-manager`
  Use to publish proposal outlines, executive summaries, and review drafts into shared docs.
- `imap-smtp-email`
  Use only when the runtime is configured for email-based draft exchange or stakeholder review.
- `researchclaw`
  Use for larger evidence packs or structured background research when installed on the gateway host.

## Working preferences

- Lead with the buyer problem and win themes before solution detail.
- Verify proof points before using them in persuasive sections.
- Prefer structured outlines, matrices, and section blueprints over long generic prose.
- Mark assumptions and missing evidence explicitly.

## Avoid

- Do not invent case studies, metrics, or buyer requirements.
- Do not default to coding tools or build/test workflows for proposal drafting.
- Do not assume access to private CRM or bid systems unless runtime provides them.
