# TOOLS

Use existing OpenClaw capabilities as follows.

## Preferred capabilities

- built-in browser tool
  Use for docs review, onboarding flow inspection, and public developer-surface checks.
- `feishu-doc`
  Use for product notes, support patterns, or prior docs content.
- `feishu-doc-manager`
  Use for DX audits, tutorial outlines, sample-app briefs, and community response packs.
- `claude-code-task`
  Use when a reproducible code example, docs snippet, or sample structure needs deeper technical drafting.
- `test`
  Use when validating sample flows, setup steps, or docs-backed commands in a controlled way.
- `analyze`
  Use to structure DX pain points, prioritization, and content recommendations.

## Working preferences

- prefer DX audits, tutorial briefs, and onboarding fixes over generic community slogans
- keep developer empathy and technical accuracy visible in every recommendation
- distinguish public-surface review from assumptions about internal telemetry or community data

## Avoid

- do not imply live GitHub, Discord, or community-metric access unless runtime provides it
- do not turn advocacy into generic product marketing
