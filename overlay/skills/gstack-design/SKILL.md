# gstack-design 设计评审与咨询

整合 gstack 的 plan-design-review 和 design-consultation 两个能力，给 OpenClaw agent 提供从设计评审到创意方案的全链路设计支持。

**承载 agent:** pc-pm, pc-frontend

**触发场景:** "设计评审"、"design review"、"设计系统"、"UI 方案"、"配色方案"、"组件规范"、"排版"、"视觉方向"、"设计审计"、"design consultation"

---

## 能力一：plan-design-review（五维度设计评分）

来源：gstack `/plan-design-review` skill。

从设计师视角对设计方案做结构化评审。交互式进行——每个维度打分后说明"做到什么能拿 10 分"。

### 五个评审维度

#### 1. 一致性 (Consistency)

| 分数 | 标准                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| 9-10 | 全站统一的设计语言——间距、圆角、阴影、色彩、交互模式完全一致，可提炼为设计规范 |
| 7-8  | 整体一致，1-2 处例外但不影响用户感知                                           |
| 5-6  | 同类组件风格不统一（如两种按钮样式混用），用户能察觉                           |
| 0-4  | 无一致性可言，每个页面像不同项目                                               |

**关键问题**:

- 同级别的按钮/卡片/标签外观是否相同？
- 间距是否遵循统一基准（4px 或 8px 倍数）？
- 图标风格是否统一（线性/面性不混用）？
- 导航栏、页头、页脚在所有页面是否一致？

#### 2. 层级 (Hierarchy)

| 分数 | 标准                                                            |
| ---- | --------------------------------------------------------------- |
| 9-10 | 视觉重心准确，用户第一眼看到最重要的内容，标题层级 h1-h4 无跳级 |
| 7-8  | 主次分明，个别区域信息密度过高或层级模糊                        |
| 5-6  | 无法判断页面重点，所有元素权重相同                              |
| 0-4  | 层级倒挂——次要信息比核心内容更显眼                              |

**关键问题**:

- 页面第一眼看到的是什么？是想要用户看到的吗？
- 标题层级是否连续（h1 > h2 > h3，无跳级）？
- 一个视图是否只有一个主 CTA？
- 信息密度是否合适（不空也不挤）？

#### 3. 可用性 (Usability)

| 分数 | 标准                                                          |
| ---- | ------------------------------------------------------------- |
| 9-10 | 核心任务 3 步内完成，表单有明确引导，错误信息有用，无认知负担 |
| 7-8  | 核心流程顺畅，个别操作路径偏长或引导不足                      |
| 5-6  | 常见任务需要多次点击或滚动才能完成，用户会迷路                |
| 0-4  | 用户无法理解如何完成核心任务                                  |

**关键问题**:

- 新用户能否 3 秒内理解页面功能？
- 核心任务的操作路径是否最短？
- 表单是否有校验提示？错误信息是否具体？
- 触摸目标是否 >= 44px？移动端可用吗？

#### 4. 美感 (Aesthetics)

| 分数 | 标准                                               |
| ---- | -------------------------------------------------- |
| 9-10 | 视觉令人愉悦，留白节奏舒适，配色和谐，细节打磨到位 |
| 7-8  | 整体美观，个别区域稍显粗糙或空旷                   |
| 5-6  | 没有明显丑但缺乏记忆点，像模板拼凑                 |
| 0-4  | 视觉混乱，配色冲突，间距无规律                     |

**关键问题**:

- 是否存在 AI Slop 模式？（紫蓝渐变、三列特性网格、彩色圆形图标等）
- 留白节奏是否舒适（不是均匀留白而是有呼吸感）？
- 配色是否和谐？对比度是否达标？
- 装饰元素是否有意义还是为了填补空白？

#### 5. 品牌契合 (Brand Fit)

| 分数 | 标准                                       |
| ---- | ------------------------------------------ |
| 9-10 | 视觉风格与品牌调性完全一致，能传达品牌个性 |
| 7-8  | 符合品牌方向，个别元素调性偏移             |
| 5-6  | 像通用模板，看不出品牌特色                 |
| 0-4  | 与品牌调性冲突（如高端品牌用卡通风格）     |

**关键问题**:

- 遮住 logo 能认出这是哪个产品吗？
- 色彩、字体、图片风格是否与品牌定位匹配？
- 品牌关键词（如"专业"、"活泼"、"极简"）是否在设计中体现？

### 综合评分规则

5 个维度取加权平均：

- 一致性 x 1.5
- 层级 x 1.5
- 可用性 x 2.0
- 美感 x 1.0
- 品牌契合 x 1.0

权重总和 7.0，综合分 = 加权总分 / 7.0，四舍五入取一位小数。

### 评审结论

| 综合分  | 结论       | 动作                         |
| ------- | ---------- | ---------------------------- |
| >= 8.0  | 通过       | 可以交付开发，关注建议项     |
| 6.0-7.9 | 有条件通过 | 解决列出的高优先级问题后交付 |
| < 6.0   | 不通过     | 需要重新设计                 |

### 与 gstack-qa 的分工

- **gstack-qa** 偏实现层面的视觉审计：像素对齐、对比度数值、响应式断点、组件渲染是否正确
- **gstack-design** 偏决策层面的设计评审：方向对不对、方案好不好、层级合不合理
- 推荐先用 design 评审方案，再用 qa 审计实现

## 能力二：design-consultation（设计系统与创意方案）

来源：gstack `/design-consultation` skill。提供建设和优化设计系统的专业咨询。

### 设计系统审计

评估设计系统的三个层面：

**Token 完整性：**

| 检查项     | 达标标准                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 颜色 token | 覆盖 primary / secondary / accent / neutral / semantic（success/warning/error/info），每色至少 5 个梯度 |
| 间距 token | 基于 4px 或 8px 基准，覆盖 0-128px 常用范围                                                             |
| 字体 token | 包含 font-family / font-size / font-weight / line-height / letter-spacing                               |
| 阴影 token | 至少 3 个层级（sm / md / lg）                                                                           |
| 圆角 token | 至少 3 个层级（sm / md / lg / full）                                                                    |
| 动效 token | duration / easing / delay 有定义                                                                        |

**组件覆盖率（按优先级）：**

P0 -- Button（主/次/文字/图标）、Input/Textarea（含校验/禁用）、Card、Modal/Dialog、Toast/Alert
P1 -- Navigation（顶栏/侧栏/面包屑/标签页）、Table（排序/筛选/分页）、Form（布局/校验/提交）、Avatar
P2 -- Badge/Tag、Tooltip、Skeleton

**文档可用性：** 每个组件是否有使用示例+Props 说明；是否有 Do/Don't 对比；是否有设计原则指南和色彩/间距使用规范。

### 配色方案评审

**对比度：** 正文 >= 4.5:1（WCAG AA），大号文本 >= 3:1，交互元素 >= 3:1，检查所有 semantic 颜色在深/浅背景上的对比度。

**色盲友好：** 用 Coblis 等工具模拟红绿色盲/蓝黄色盲视角；不能仅依赖颜色传达信息（配合图标或文字）；状态色不能只有红绿区分。

**品牌一致性：** 主色是否与品牌色一致；辅助色是否与主色和谐；配色是否能传达品牌个性（温暖/冷静/活力/专业）。

### 排版系统评审

| 检查项   | 达标标准                                    |
| -------- | ------------------------------------------- |
| 字体层级 | h1-h4 + body + caption + overline 至少 6 级 |
| 字号梯度 | 相邻层级至少差 2px，避免微小差异            |
| 行高     | 正文 1.5-1.75，标题 1.2-1.4                 |
| 字间距   | 大写标题 +2%~5%，正文默认                   |
| 最大行宽 | 正文 45-75 字符（中文 25-40 字）            |

### 创意方向探索

给出 2-3 个设计方向，每个方向包含：关键词（3 个形容词）、参考案例、核心视觉特征（配色/排版/图形/动效）、适用场景、风险。

## 使用流程

| 流程           | 触发场景                             | 步骤                                                                                                            |
| -------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 从零建设计系统 | "帮我们建设计系统"、"从零搭 UI 规范" | design-consultation（审计+定方向）-> 创意方向探索 -> 选定方向 -> plan-design-review（评审）-> 细化 token 和组件 |
| 评审现有设计   | "设计评审"、"看看 UI 有什么问题"     | plan-design-review（五维度评分）-> 输出问题列表和优先级 -> 针对性修复建议                                       |
| 配色/排版专项  | "配色方案"、"排版有问题"、"字体规范" | design-consultation（配色/排版审计）-> 输出对比度、色盲、品牌一致性报告 -> 优化方案                             |
| 创意方向探索   | "视觉方向"、"几个方案选一个"         | design-consultation（创意方向）-> 2-3 个方向选项 -> 对比表 -> 推荐 + 理由                                       |

## 注意事项

1. **这个 skill 不写代码** -- 只产出设计评审文档和方案建议，不直接修改 CSS/组件代码
2. **需要视觉输入** -- 评审时最好有设计稿截图或页面 URL，纯文字描述设计会降低评审质量
3. **与 gstack-qa 互补** -- design 评审方向和决策，qa 审计实现细节，不要重复
4. **AI Slop 警觉** -- 审美维度要特别检查 AI 生成模板的 10 个反模式（见 gstack-qa 文档）
5. **IM 渠道精简** -- 在企微/飞书中输出时，用评分表 + Top 3 问题即可，详细报告用文件输出
6. **不要两边讨好** -- 评审结论必须明确（通过/不通过），有条件通过要列出具体条件
