# gstack-security

安全威胁建模与安全评审技能。基于 STRIDE 模型进行系统性威胁分析，输出标准化安全评审报告。

## 承载 Agent

- **cto** — 技术决策层安全评审
- **pc-devops** — 基础设施与部署安全审计

## 触发场景

- "安全评审"、"威胁建模"、"安全检查"
- "security review"、"threat modeling"、"security audit"
- "渗透测试"、"漏洞扫描"、"合规检查"

## 1. 威胁建模 (STRIDE)

对目标系统逐类分析，每类威胁给出检查清单和常见攻击向量。

### 1.1 Spoofing（仿冒）

**检查清单：**

- [ ] 认证机制是否防止身份伪造（MFA、证书绑定）
- [ ] API 调用是否验证调用方身份（Token 校验、签名验证）
- [ ] 是否存在默认凭据或硬编码密钥
- [ ] 会话令牌是否可被预测或劫持

**常见攻击向量：**

- 窃取 JWT/Session Token 后重放请求
- 伪造来源 IP（X-Forwarded-For 注入）
- 利用 OAuth 配置错误进行授权码拦截
- 中间人攻击（MITM）截获凭据

### 1.2 Tampering（篡改）

**检查清单：**

- [ ] 数据传输是否使用 TLS 加密
- [ ] 关键数据是否有完整性校验（签名、HMAC）
- [ ] API 参数是否做服务端校验（不信任客户端输入）
- [ ] 文件上传是否有类型与内容校验

**常见攻击向量：**

- 修改请求参数（价格、权限、ID）
- 上传恶意文件替代合法资源
- 篡改本地存储的配置或 Token
- 中间人修改 API 响应内容

### 1.3 Repudiation（抵赖）

**检查清单：**

- [ ] 关键操作是否有审计日志
- [ ] 日志是否包含用户身份、时间戳、操作详情
- [ ] 日志是否防篡改（只写存储、远程汇聚）
- [ ] 是否存在不可抵赖机制（数字签名）

**常见攻击向量：**

- 删除或修改审计日志掩盖操作痕迹
- 共享账号导致操作无法归因
- 缺少操作日志导致事后无法追溯

### 1.4 Information Disclosure（信息泄露）

**检查清单：**

- [ ] 敏感数据是否加密存储（AES-256、KMS）
- [ ] API 响应是否过滤敏感字段（密码哈希、内部 ID）
- [ ] 错误信息是否泄露内部实现细节
- [ ] 日志是否脱敏（不含密码、Token、PII）

**常见攻击向量：**

- 遍历 API 端点获取其他用户数据（IDOR）
- 错误堆栈暴露技术栈和路径信息
- 日志明文记录敏感数据
- 未加密备份文件泄露

### 1.5 Denial of Service（拒绝服务）

**检查清单：**

- [ ] 是否有速率限制（Rate Limiting）
- [ ] 是否有请求大小限制和超时设置
- [ ] 关键资源是否有配额保护
- [ ] 是否有降级和熔断机制

**常见攻击向量：**

- 大文件上传耗尽存储或内存
- 复杂查询导致数据库 CPU 飙升
- 大量并发请求耗尽连接池
- 触发昂贵计算（正则 ReDoS、大数运算）

### 1.6 Elevation of Privilege（权限提升）

**检查清单：**

- [ ] 是否实施最小权限原则
- [ ] RBAC 权限是否覆盖所有敏感操作
- [ ] 是否存在水平越权（A 操作 B 的资源）
- [ ] 是否存在垂直越权（普通用户执行管理员操作）

**常见攻击向量：**

- 修改请求中的 user_id 操作他人数据
- 利用角色切换接口提权
- JWT 中 role 字段未服务端校验
- 利用管理后台未鉴权接口

## 2. 安全检查清单

### 2.1 认证与授权

| 检查项       | 要求                             |
| ------------ | -------------------------------- |
| JWT 管理     | 短有效期 + Refresh Token 轮换    |
| Session 管理 | HttpOnly、Secure、SameSite 属性  |
| RBAC         | 角色定义清晰，权限粒度到操作级别 |
| API Key      | 定期轮换，支持即时吊销           |
| 密码策略     | 最小长度 + 复杂度 + 防暴力破解   |

### 2.2 输入校验

| 攻击类型 | 防御措施                          |
| -------- | --------------------------------- |
| SQL 注入 | 参数化查询，禁止拼接 SQL          |
| XSS      | 输出编码 + CSP 头，避免 innerHTML |
| CSRF     | SameSite Cookie + CSRF Token      |
| 命令注入 | 禁止 shell 拼接，使用参数化调用   |
| 路径遍历 | 校验并规范化路径，限制访问范围    |

### 2.3 数据保护

- **传输加密**：全站 HTTPS，TLS 1.2+，HSTS 启用
- **存储加密**：敏感字段 AES-256 加密，密钥通过 KMS 管理
- **日志脱敏**：密码、Token、手机号、身份证号等自动掩码
- **数据分类**：按敏感级别（公开/内部/机密/绝密）分级处理

### 2.4 基础设施安全

- **HTTPS**：有效证书，禁用弱加密套件
- **CORS**：白名单域名，禁止 `Access-Control-Allow-Origin: *`
- **CSP**：限制脚本/样式/图片来源，禁止 unsafe-inline
- **依赖安全**：定期 `npm audit` / `pnpm audit`，关注 CVE 通告
- **容器安全**：最小基础镜像，非 root 运行，只读文件系统

### 2.5 LLM 特有安全

| 风险        | 描述                             | 防御                    |
| ----------- | -------------------------------- | ----------------------- |
| Prompt 注入 | 恶意输入操纵 LLM 行为            | 输入过滤 + 系统提示隔离 |
| 数据泄露    | LLM 泄露训练或上下文中的敏感信息 | 输出过滤 + 上下文最小化 |
| 幻觉风险    | LLM 生成虚假但可信的信息         | 事实校验 + 置信度标注   |
| 供应链投毒  | 恶意 Prompt 通过模板/插件注入    | 模板审计 + 来源验证     |
| 越狱攻击    | 绕过安全限制获取未授权输出       | 多层防御 + 行为监控     |

## 3. 严重程度分级

### Critical（严重）

- **定义**：可被远程利用，无需认证或仅需低权限，直接影响用户数据或系统可用性
- **示例**：未授权数据访问、远程代码执行、SQL 注入导致全库泄露
- **响应**：立即修复，24 小时内完成，通知受影响用户

### High（高危）

- **定义**：需要认证但可提权，或影响部分用户数据安全
- **示例**：水平越权访问、存储型 XSS、敏感信息明文存储
- **响应**：优先修复，72 小时内完成

### Medium（中危）

- **定义**：信息泄露但不涉及敏感数据，或需要特殊条件触发
- **示例**：错误信息泄露技术栈、缺少速率限制、CORS 配置过宽
- **响应**：计划修复，下一个迭代完成

### Low（低危）

- **定义**：安全最佳实践建议，无直接安全风险
- **示例**：缺少安全响应头、日志级别过高、Cookie 未设置 Secure 属性
- **响应**：择机修复，纳入技术债务管理

## 4. 输出格式

### 4.1 威胁模型文档

```markdown
# 威胁模型：[系统/模块名称]

## 系统概述

- 架构图 / 数据流图
- 信任边界划分

## 威胁分析 (STRIDE)

| #   | 威胁类型 | 威胁描述 | 攻击向量 | 影响范围 | 现有控制 | 风险等级 |
| --- | -------- | -------- | -------- | -------- | -------- | -------- |

## 风险矩阵

- 高影响 + 高概率 → Critical
- 高影响 + 低概率 → High
- 低影响 + 高概率 → Medium
- 低影响 + 低概率 → Low
```

### 4.2 安全评审报告

```markdown
# 安全评审报告

## 评审范围

- 目标系统 / 代码库 / 基础设施
- 评审时间与参与者

## 发现列表

| #   | 发现 | 严重度 | 位置 | 描述 | 修复建议 | 状态 |
| --- | ---- | ------ | ---- | ---- | -------- | ---- |

## 统计摘要

- Critical: X | High: X | Medium: X | Low: X
- 总体安全评分: X/100

## 修复优先级排序

1. [Critical 发现修复计划]
2. [High 发现修复计划]
```

### 4.3 合规检查清单

```markdown
# 合规检查清单

## 检查类别

- [ ] 认证与授权
- [ ] 输入校验
- [ ] 数据保护
- [ ] 基础设施安全
- [ ] LLM 特有安全
- [ ] 日志与审计
- [ ] 依赖安全

## 合规状态

| 类别 | 通过/总数 | 合规率 |
| ---- | --------- | ------ |
```

## 5. 使用指南

### 评审流程

1. **范围界定** — 明确评审边界（系统、模块、代码库）
2. **威胁建模** — 按 STRIDE 六类逐项分析
3. **检查清单** — 逐项验证安全控制措施
4. **发现整理** — 按严重程度分级，给出修复建议
5. **报告输出** — 生成威胁模型文档、安全评审报告、合规检查清单

### 集成方式

在 agent 配置中引用本技能，触发关键词自动激活。支持与其他技能（如 gstack 浏览器测试）联动进行渗透验证。
