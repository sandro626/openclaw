# gstack-retro 复盘与趋势分析

自动从 git、PR、issues、监控数据中提取信息，多维度复盘，生成趋势报告和改进行动项。

承载 agent: ops, pc-ceo_assistant
触发关键词: "复盘"、"retro"、"回顾"、"总结"、"趋势分析"

---

## 复盘流程

### 1. 收集阶段

```bash
# Git 提交记录
git log --since="<起>" --until="<止>" --oneline --no-merges --format="%h|%an|%s"
# PR 合并统计
gh pr list --state merged --search "merged:<起>..<止>" --json title,author,mergedAt,additions,deletions
# Issue 统计
gh issue list --state all --search "created:<起>..<止>" --json title,labels,state,closedAt
# 代码变更量
git log --since="<起>" --until="<止>" --numstat --format=""
```

可补充：监控告警、部署记录、测试报告。

### 2. 分类阶段

| 类别   | 识别规则                             |
| ------ | ------------------------------------ |
| 功能   | feat/feature 前缀，PR label: feature |
| 修复   | fix/bugfix 前缀，关联 issue          |
| 性能   | perf 前缀，涉及查询/加载/缓存        |
| 安全   | security/dependabot 前缀，依赖升级   |
| 技术债 | refactor/chore 前缀，无功能变化      |
| 文档   | docs 前缀，.md 文件变更              |

### 3. 分析阶段

- **做得好的**：高价值交付、效率提升实践、协作成功案例
- **做得不好的**：反复出现的问题、超时工作项、未根治的临时修复
- **可以改进的**：流程优化、自动化机会、知识共享缺口

### 4. 行动阶段

每个行动项关联具体复盘发现，优先级 P0/P1/P2，负责人明确到个人。

```
# | 行动项 | 负责人 | 截止日期 | 优先级 | 关联发现
```

## 趋势总结

### 周期粒度

| 周期 | 默认范围      | 适用场景         |
| ---- | ------------- | ---------------- |
| 周报 | 最近 4 周     | 日常节奏跟踪     |
| 月报 | 最近 3 个月   | 迭代级别回顾     |
| 季报 | 最近 4 个季度 | 战略级别趋势分析 |

### 核心指标

- **代码量**：周新增/删除行数趋势
- **PR 统计**：新增/合并/关闭数，平均 merge 时间，审查轮次分布
- **Bug 趋势**：新增 vs 修复数，平均修复时长，severity 分布
- **技术债**：refactor 提交占比，TODO/FIXME 数量变化，过期依赖数


## 多维度复盘

### 交付维度

| 指标         | 计算方式                  | 目标   |
| ------------ | ------------------------- | ------ |
| 按时交付率   | 按计划完成数/总计划数     | >= 80% |
| Scope 变化率 | 新增需求数/原始需求数     | <= 20% |
| 需求吞吐量   | 完成 story point/迭代天数 | 趋稳   |
| 需求拆分质量 | 单 PR 平均改动文件数      | <= 10  |

### 质量维度

| 指标       | 计算方式                  | 目标   |
| ---------- | ------------------------- | ------ |
| Bug 密度   | 新增 bug 数/合并 PR 数    | <= 0.3 |
| 回归率     | 重开 bug 数/总关闭 bug 数 | <= 5%  |
| 测试覆盖率 | 覆盖率数值变化            | 不下降 |
| 线上故障   | 周期内生产环境故障次数    | = 0    |

### 协作维度

| 指标           | 计算方式                 | 目标   |
| -------------- | ------------------------ | ------ |
| PR Review 速度 | 平均首次 review 响应时间 | <= 4h  |
| PR 瓶颈环节    | review 轮次最多 PR 分析  | 无堆积 |
| 知识共享       | 文档更新频率、分享会次数 | 每周有 |

### 技术维度

| 指标       | 计算方式                  | 目标     |
| ---------- | ------------------------- | -------- |
| 技术债增减 | refactor 提交占比变化     | >= 15%   |
| 依赖健康度 | 过期/有漏洞依赖数变化     | 持续减少 |
| 架构演进   | 模块依赖复杂度变化        | 不恶化   |
| 自动化程度 | CI 通过率、自动部署成功率 | >= 95%   |

## 使用示例

**周复盘**：请对本周进行复盘，重点关注 PR review 速度、Bug 修复跟进、上周行动项进展。

**月度趋势**：生成最近 3 个月趋势报告，包括代码量、PR 数、Bug 积压、技术债变化及月度对比。

**专项复盘**：对上周线上故障进行专项复盘：时间线、根因、影响范围、预防行动项。
