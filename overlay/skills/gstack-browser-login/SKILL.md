# gstack-browser-login: 认证页面测试前置

为需要登录的页面测试提供完整的认证前置流程。

**承载 agent:** pc-pctester, dev, ops

**触发场景:** "登录测试"、"cookie 设置"、"认证测试"、"需要登录才能测"、"登录态"

本 skill 使用 OpenClaw 自带的 `browser` 插件完成所有浏览器操作。不引入独立 daemon，不依赖 `~/.gstack/browse.json`。

---

## 一、登录流程

### 标准登录

```
1. 使用 browser 插件导航到登录页
2. 识别登录表单元素（用户名/密码/提交按钮）
3. 填写用户名和密码，处理验证码（如有）
4. 提交表单，验证登录成功
5. 截图保存：login-success-{domain}-{timestamp}.png
```

### 表单识别策略

| 元素   | 优先选择器                                      | 备选                                             |
| ------ | ----------------------------------------------- | ------------------------------------------------ |
| 用户名 | `input[type="text"]`, `input[name*="user"]`     | `input[name*="email"]`, `input[name*="account"]` |
| 密码   | `input[type="password"]`                        | `input[name*="pass"]`                            |
| 验证码 | `input[name*="captcha"]`, `input[name*="code"]` | `img[src*="captcha"]` 旁的 input                 |
| 提交   | `button[type="submit"]`                         | `input[type="submit"]`, 含"登录/Login"文本的按钮 |

### 登录成功判定（满足任一）

- URL 变化（离开登录页）
- 出现预期 cookie（`sessionid`, `token`, `jwt`）
- 页面出现用户名/头像/退出按钮
- 登录表单消失

## 二、多因素认证（MFA）处理

### SMS 验证码

1. 检测是否跳转到验证码页面
2. 提示用户提供验证码（agent 不自动获取）
3. 填写并提交，验证登录结果

### TOTP

1. 用户提供 TOTP secret
2. Agent 计算当前验证码并填写
3. TOTP secret 不记录在日志中

### SSO / OAuth

| SSO 类型        | 处理方式                 |
| --------------- | ------------------------ |
| 企业微信扫码    | 人工扫码，agent 等待回调 |
| 钉钉登录        | 人工扫码或输入验证码     |
| LDAP/AD         | agent 可直接填写         |
| CAS 统一认证    | agent 可直接填写         |
| OAuth2 授权码流 | 需人工确认授权页         |

## 三、Cookie 管理

### 导出

登录成功后调用 browser 插件获取 cookie，过滤目标域名相关项，记录 cookie 名称和有效期，不输出 cookie 值到日志。

### 导入（跳过登录）

1. 接收 cookie 数据（用户提供或上次会话保存）
2. 注入到浏览器上下文
3. 导航到目标页面验证生效

### 有效期检查

读取 `expires`/`max-age`，标记已过期/即将过期（< 5 分钟）/有效，即将过期给出警告。

### 多账号切换

导出当前 cookie -> 清除 -> 导入新账号 cookie -> 验证切换成功。每次操作截图留证。

---

## 四、安全规范

### 密码保护

- 日志、报告、截图中密码一律 `[REDACTED]`
- 密码不出现在命令行参数中
- 截图前确认密码输入框被遮盖
- 报告只记录"使用账号 xxx@xxx 登录成功"

### Cookie 保护

- Cookie 值不写入磁盘（仅浏览器内存上下文）
- 日志中 cookie 值显示为 `[COOKIE_REDACTED]`
- 不跨会话持久化，浏览器上下文销毁后自动清除

### 登录态清理

测试完成后清除所有 cookie，验证已退出登录状态，确认无残留。

## 五、与 gstack-qa 配合

### 登录后进入 QA

```
1. 完成登录 -> 保存登录态截图
2. 调用 gstack-qa skill 开始测试
3. QA 过程中复用已建立的登录态
4. 登录态失效时重新登录后继续
```

### 权限相关测试

```
1. 管理员登录 -> 权限测试 -> 记录结果 -> 清除登录态
2. 普通用户登录 -> 权限测试 -> 记录结果 -> 清除登录态
3. 受限账号登录 -> 权限测试 -> 记录结果 -> 清除登录态
4. 对比各角色页面差异（可见元素、可操作按钮、数据范围）
```

### 报告输出

| 项目          | 结果                       |
| ------------- | -------------------------- |
| 登录页 URL    | {url}                      |
| 认证方式      | 表单/SMS/TOTP/SSO          |
| 登录是否成功  | 是/否                      |
| 登录耗时      | {N} 秒                     |
| 登录态截图    | login-success-{domain}.png |
| Cookie 有效期 | {duration}                 |
| 安全检查      | 密码已脱敏/无 cookie 泄露  |
